Protocol Failure Brief No. 07 / Replay

The physics holds. The bookkeeping breaks.

Quantum key distribution is unbreakable in exactly one place: the quantum channel. Everything else is ordinary software. A replay attack ignores the photons entirely and re-sends yesterday's classical messages — and if nothing checks their freshness, the eavesdropper becomes the endpoint.

By Malcolm R. Smith — Savvy Security LLC

What QKD guarantees
Photons can't be copied

No-cloning means any measurement Eve makes disturbs the state. Interception shows up as a rising error rate.

What it assumes
An authenticated classical channel

Sifting, error correction and privacy amplification all run over the public internet. Every security proof takes their authenticity as given.

What replay attacks
That assumption, not the qubits

Record a valid transcript once. Send it again later. If the tags still verify, the quantum layer never notices it was cut out of the loop.

How the break unfolds

  1. 01
    Keys are exchanged

    Photons fly, Bob measures in random bases. Eve cannot copy them. The physics is intact.

  2. 02
    A side conversation runs

    Basis sifting, error correction and privacy amplification happen in plain classical messages.

  3. 03
    Eve records it

    She logs the whole transcript, authentication tags included. No interception alarm fires, because nothing was intercepted.

  4. 04
    Eve replays it

    In the next session she sends the stored messages verbatim. With no freshness check, an old valid tag is still a valid tag.

  5. 05
    The channel is hers

    Eve plays Alice to Bob and Bob to Alice. Both error rates look clean — the qubits were never the target.

Where it bites in practice

  • Authentication key material reused across sessions — Wegman–Carter tags lose their information-theoretic guarantee the moment the key repeats.
  • Tags that cover a single message but not the session it belongs to.
  • No monotonic counter on sifting and reconciliation rounds.
  • Deployment treating the classical link as “just plumbing” outside the threat model.
  • Key stores that will re-issue a retired session key to an application on request.

What actually stops it

  • A fresh, never-reused authentication key for every tag, drawn from the previous session's key material.
  • Every tag bound to a session ID plus a monotonic counter, both inside the authenticated data.
  • Authenticate a hash of the complete transcript at session close, not message by message.
  • Two-way key confirmation before the key is released to any application.
  • Retire, log and refuse to re-issue every session key.

A replay attack never violates no-cloning. It attacks the assumption layer wrapped around it — which is why “quantum-secure” is a property of a system, not of a photon.

NOTE — Standard QKD security proofs (BB84 and successors) are stated relative to an authenticated classical channel. Replay resistance is an implementation obligation, not a physical consequence.
SCOPE — Applies equally to prepare-and-measure and entanglement-based systems, and to the key-management layer that hands keys to applications.
